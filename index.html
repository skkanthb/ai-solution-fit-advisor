What this is

A decision aid for AI architects, SI practices, and presales teams. It breaks an enterprise use case into steps and recommends a solution pattern for each: rules, matching, tabular ML, forecasting, optimization, document AI, LLM patterns, agents, or keeping a person in charge.

Most use cases turn out to be mixed. A credit hold release process is a rule, a risk model, and an optional LLM summary, not "an AI agent for credit".

How it decides

  • Twelve questions describe one step: what it must do, input type, whether the logic is explicit, available history, volume, latency, error cost, explainability, whether it writes to a system of record, data sensitivity, format variability, and constraints.
  • An ordered rulebook maps the answers to a pattern. The rule that fired is shown with every result.
  • Autonomy, controls, model candidates, and the evaluation plan are derived from the pattern and the answers.
  • No LLM is involved in the decision. The same answers always give the same result.

Limits

  • The library profiles and notes reflect one practitioner's ERP and supply chain experience. They have not been validated against measured project outcomes.
  • Real steps are often borderline between two patterns. Treat the output as a starting position for an architecture review, not a verdict.
  • Model names go stale. The registry is dated; check current versions and your contract terms.
  • It does not estimate cost or ROI, and it does not look at your data. Data quality problems will break any pattern.
  • Scope is O2C, P2P, and logistics. Planning, manufacturing, and service are not covered yet.
