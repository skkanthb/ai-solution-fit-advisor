## Prompt

```
I'm an enterprise architect scoping an AI solution for this ERP / supply chain use case:

Procurement policy and contract Q&A: Buyers and requesters email procurement to ask which policy applies or what a contract says about terms, rebates, or renewal.

What AI approach and models would you recommend?
```

## Answer

For “procurement policy + contract Q&A from email,” the most reliable enterprise pattern is **RAG (retrieval‑augmented generation) over governed content**, wrapped in **workflow + citations + permissions**. Avoid “train a model on contracts” as the primary approach; you’ll want deterministic retrieval, strong access control, and auditable answers.

## Recommended AI approach (high level)

### 1) Ingestion + normalization (policies + contracts + metadata)
- **Sources**: contract repository/CLM, SharePoint/Drive, ERP attachments, policy wiki/PDFs, emails (for context only).
- **Process**:
  - OCR + layout parsing for PDFs/scans.
  - Split into meaningful chunks (sections/clauses), preserving hierarchy (document → section → clause).
  - Extract metadata: supplier, category, effective dates, renewal/term dates, jurisdiction, contract ID, amendments, SOW linkages.
- **Why**: Q&A needs clause-level recall, and contracts often have amendments that supersede base language.

### 2) Retrieval layer (hybrid search + re-ranking + access control)
- **Hybrid retrieval**: combine keyword/BM25 + vector embeddings (best practice for legal/procurement language).
- **Re-ranking**: a cross-encoder reranker to push the most relevant clauses to the top.
- **Security trimming**: enforce ACLs at query time (user identity → allowed documents/clauses).
- **Why**: contract questions often hinge on exact terms; retrieval quality matters more than generation quality.

### 3) Answer generation with grounding + citations + “don’t know”
- Use an LLM to:
  - Interpret the email question,
  - Retrieve supporting clauses,
  - Produce a structured answer **with citations** (contract name/ID, clause number, page/section, effective date),
  - Provide “cannot determine” if retrieval is insufficient or the user lacks access.
- Add **response templates**:
  - Policy questions: “Applicable policy + excerpt + link + exceptions + escalation path”
  - Contract questions: “Term/rebate/renewal summary + exact clause excerpts + effective dates + amendment precedence”
- **Why**: procurement needs traceability and auditability.

### 4) Workflow + human-in-the-loop (where it matters)
- **Auto-answer** low-risk policy questions.
- **Draft response** for contract interpretation, rebates, renewals, exceptions, or anything with financial/legal impact.
- Route to procurement/legal for approval; log final answer back to ticket/email thread.
- **Why**: reduces risk and builds trust while still saving time.

### 5) Guardrails and compliance
- “Not legal advice” disclaimer where appropriate.
- PII/PHI detection + redaction when indexing and when responding (depending on your environment).
- Data residency and encryption requirements.
- Full audit logs: retrieved passages, model version, prompts, user, timestamp.

## Model recommendations by component

### A) Embeddings model (for vector search)
Pick one strong, enterprise-grade embedding model and standardize on it:
- **OpenAI**: `text-embedding-3-large` (very strong semantic retrieval; good across domains).
- **Azure OpenAI equivalent** if you’re on Microsoft stack.
- **If you must stay fully self-hosted**: a high-quality sentence embedding model (e.g., modern BGE-style large embeddings) deployed in your environment.

**Notes**:
- Consider **separate embeddings for policies vs contracts** only if retrieval tests show benefit; otherwise keep one index with good metadata filters.
- Chunk at clause/section granularity; keep overlap small; store headings.

### B) Reranker (cross-encoder)
A reranker materially improves “find the right clause”:
- If your platform supports it, use a **cross-encoder reranker** (vendor-managed or self-hosted).
- Otherwise, use LLM-based “rerank top N passages” as a fallback (costlier/slower).

### C) LLM for Q&A generation (the “writer”)
You need strong instruction following + low hallucination tendency + good citation behavior:
- **OpenAI**: GPT‑4.1 (best reliability) or GPT‑4o (often cheaper/faster with strong quality).
- **Azure OpenAI** versions of the above if you need Microsoft governance.
- For more cost control: use a smaller model for drafting plus escalation to a larger one when confidence is low.

**Pattern**:
- Use a **two-step**: (1) retrieval + (2) answer with “only use provided sources” constraint.
- Ask the model to output:
  - Answer,
  - Citations (doc, section, quote),
  - Confidence + “missing info” checklist,
  - Suggested follow-up questions.

### D) Optional: fine-tuning / SLMs
Fine-tuning is **not the first lever** here. Consider it later for:
- **Email intent classification** (policy vs contract vs vendor onboarding vs pricing).
- **Entity extraction** (supplier name, contract ID, category, renewal date).
- **Standard response formatting** if you need very consistent style.

## Architecture pattern (practical reference)
1. **Email arrives** → classify intent + extract entities.
2. **Policy/contract selection** via metadata filters (supplier/category/effective date) + hybrid search.
3. **Retrieve top clauses** → rerank.
4. **Generate answer** with citations + links.
5. **Risk scoring**:
   - If “rebates/renewals/penalties/termination/exception request” → require approval.
6. **Send response** (or draft) + log everything.

---

## What to avoid
- **Training a model to “know your contracts.”** It won’t stay current, is hard to govern, and creates audit risk.
- **Pure vector search without keyword support.** Clause numbers, defined terms, and exhibit references often need lexical matching.
- **Answers without citations.** Procurement users will not trust it, and you can’t defend it in audits.

---

## Implementation shortlist (if you want to pick stack options)
- **Vector DB / search**: Azure AI Search, Elasticsearch/OpenSearch (hybrid), Pinecone, Weaviate, pgvector—choose based on your enterprise standards and ACL support.
- **Orchestration**: LangGraph/LangChain, Semantic Kernel, or a native platform agent framework.
- **Document parsing**: Azure Document Intelligence, AWS Textract, or equivalent OCR/layout tools.

---

## Key evaluation criteria (use in your POC)
- **Clause recall@k** on a labeled set of questions (rebate, renewal, termination, SLA, payment terms).
- **Citation accuracy** (does the cited text actually support the statement?).
- **Access control tests** (no leakage across suppliers/regions).
- **Amendment precedence correctness** (amendment overrides base agreement).
- **Latency + cost per email**.
